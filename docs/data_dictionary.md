# Data Dictionary

This document defines every table in the processed (star schema) layer, its grain, its
columns, and — critically — exactly how it was derived from the raw source files. Anyone
reviewing this portfolio project should be able to trace any column back to its origin.

---

## Source Files (Raw Zone — `s3://<bucket>/raw/`)

| File | Origin | Notes |
|---|---|---|
| `2019-Oct.csv` … `2020-Feb.csv` (or any subset) | Kaggle: eCommerce Events History in Cosmetics Shop | One row per event. ~20M rows total across all months; use 1–2 months for a portfolio-sized project. |
| `olist_orders_dataset.csv` | Kaggle: Olist Brazilian E-Commerce | One row per order |
| `olist_order_payments_dataset.csv` | Kaggle: Olist Brazilian E-Commerce | One row per payment installment on an order |
| `olist_customers_dataset.csv` | Kaggle: Olist Brazilian E-Commerce | Customer ID ↔ region (state) lookup |
| `app_errors_synthetic.csv` | Generated by `src/transformations.py` | See "Synthetic Errors" section below |

## 1. `dim_users`

**Grain:** one row per `user_id`.

| Column | Type | Source / Derivation |
|---|---|---|
| `user_id` | bigint | Raw `user_id` from the cosmetics-shop events file |
| `registration_date` | date | `MIN(event_time)` for that user — first time they were observed |
| `region` | string | Sampled without replacement from the real distribution of Brazilian states in `olist_customers_dataset.csv` (`customer_state`), assigned per user_id (seeded random, reproducible) |
| `device_type` | string | Most frequently occurring device signal for that user across their events (see `device_type` derivation under `fact_events`) |
| `customer_segment` | string | Computed post-hoc from `fact_transactions`: users are bucketed into `High Value` (top 20% lifetime spend), `Mid Value` (next 30%), `Low Value` (bottom 50%), `Non-Purchaser` (no completed transaction) |

## 2. `fact_events`

**Grain:** one row per application event.

| Column | Type | Source / Derivation |
|---|---|---|
| `event_id` | string | Surrogate key generated as `ROW_NUMBER()` over the source file (source has no native event id) |
| `user_id` | bigint | Raw `user_id` |
| `event_type` | string | Mapped from raw `event_type` (`view`, `cart`, `remove_from_cart`, `purchase`) into the app-style taxonomy used in this project: `view`→`Product View`, `cart`→`Add to Cart`, `remove_from_cart`→`Remove from Cart`, `purchase`→`Checkout`. `Login`/`Logout`/`Search`/`Payment` events are synthesized per session (see below) since the raw clickstream dataset is product-interaction-only |
| `event_timestamp` | timestamp | Raw `event_time` |
| `session_id` | string | Raw `user_session` (native session UUID from source — real, not synthetic) |
| `device_type` | string | The raw dataset has no device column, so device is simulated once per `user_session` (not per event) using a realistic split (`Mobile` 58%, `Desktop` 35%, `Tablet` 7%, matching typical e-commerce traffic mixes) — seeded random for reproducibility |
| `application_version` | string | Simulated once per `user_session` from a small set of realistic semantic versions (`3.4.0`, `3.4.1`, `3.5.0`, `3.5.2`, `3.6.0`), weighted toward the two most recent |

**Why Login/Logout/Search/Payment are synthesized:** the source clickstream captures
product interactions only. To make the funnel realistic (Login → Search → Product View →
Add to Cart → Checkout → Payment), a `Login` event is inserted at the start of each
session and a `Payment` event immediately follows any `purchase`-derived `Checkout` event
with a small probability of failure (see `fact_transactions.transaction_status`). This
logic lives in `src/transformations.py::build_events()` and is fully commented.

## 3. `dim_sessions`

**Grain:** one row per `session_id`.

| Column | Type | Source / Derivation |
|---|---|---|
| `session_id` | string | Raw `user_session` |
| `user_id` | bigint | From `fact_events` |
| `session_start` | timestamp | `MIN(event_timestamp)` for the session |
| `session_end` | timestamp | `MAX(event_timestamp)` for the session |
| `session_duration_sec` | int | `session_end - session_start` |
| `event_count` | int | `COUNT(*)` events in session |
| `device_type` | string | From `fact_events` (constant within a session by construction) |
| `converted` | boolean | `TRUE` if session contains a `Checkout` event |

## 4. `fact_transactions`

**Grain:** one row per transaction (order).

| Column | Type | Source / Derivation |
|---|---|---|
| `transaction_id` | string | Raw Olist `order_id` |
| `user_id` | bigint | Olist `customer_unique_id` deterministically remapped onto the cosmetics-shop `user_id` pool (hash-based mapping so the join is stable and reproducible — documented in `transformations.py::map_customers_to_users()`) |
| `transaction_date` | timestamp | Olist `order_purchase_timestamp` |
| `transaction_amount` | decimal | Olist `payment_value` from `olist_order_payments_dataset.csv` (summed if an order has multiple payment installments) |
| `payment_method` | string | Olist `payment_type` (`credit_card`, `boleto`, `voucher`, `debit_card`) |
| `transaction_status` | string | Derived from Olist `order_status`: `delivered`/`shipped`/`invoiced` → `Completed`; `canceled` → `Failed`; `processing`/`approved` → `Pending` |

## 5. `fact_errors` (Synthetic)

**Grain:** one row per application error event.

| Column | Type | Source / Derivation |
|---|---|---|
| `error_id` | string | Surrogate key |
| `user_id` | bigint | Sampled from the real `user_id` pool, weighted toward users who had short/abandoned sessions (i.e., errors are correlated with drop-off, not random) |
| `error_type` | string | Sampled from a realistic taxonomy: `PaymentGatewayTimeout`, `SessionExpired`, `APIError5xx`, `NetworkTimeout`, `NullPointerException`, `AuthenticationFailure`, `OutOfMemory` — with `PaymentGatewayTimeout` weighted higher during/after `Checkout` events to let the dashboard show a believable "errors hurt conversion" story |
| `error_timestamp` | timestamp | Sampled within an existing session's time window, or shortly after, for realism |
| `device_type` | string | Skewed toward `Mobile` (mobile apps generate more crash/network errors in real telemetry) |
| `application_version` | string | Skewed toward the newest version (`3.6.0`) to simulate a "new release introduced a regression" narrative — a common, realistic analyst finding |

**Generation is fully parameterized and seeded** (`random_state=42`) in
`src/transformations.py::generate_synthetic_errors()`, and the function docstring states
every probability used, so the logic is auditable, not a black box.

## Referential Integrity

- Every `fact_events.user_id`, `fact_transactions.user_id`, `fact_errors.user_id` exists in `dim_users.user_id`.
- Every `fact_events.session_id` exists in `dim_sessions.session_id`.
- Enforced and tested in `src/data_validation.py` and re-checked in `sql/data_quality_checks.sql`.
